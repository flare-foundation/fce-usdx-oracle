What & why

USDX's only real market (BitMart) is down, so there's no price for FTSO. We publish a backing-based price instead: a TEE extension reads on-chain supply, asks Hex for reserves, publishes the ratio as an FTSO custom feed. The TEE holds the API keys and is pinned by a registered code hash, so consumers verify what computed the price rather than trusting an operator.

supply  = USDX totalSupply on Flare + Ethereum + Songbird  (minus exclusions)
backing = bond reserves (public API) + cash reserves (private API)
price   = min(1, backing / supply)      capped at 1: USDX redeems at par

✅ Resolved (3 Aug 2026): the reserves figure is a bank-reported balance. Was: "⚠ Blocker: the reserves figure may be pinned to supply".

current_reserves_amount is sourced from Hex's banking provider — the actual balance of the reserve account, not a metric computed from chain data. It equals on-chain supply to the cent because Hex operates 1:1: a redemption burns tokens and wires the same amount out of the account. That is exactly what the observed behaviour (to-the-cent match; tracking the 1M burn within hours) looks like from outside.

The detection capability is real: a bank balance can fall below supply — any outflow with no matching burn (theft, account freeze, operational loss) — which is precisely the depeg event this feed exists to catch.

Remaining, as ordinary diligence: written confirmation from Hex of the provenance and semantics (Questions for Hex, #1). Evidence and history: the findings doc, §1.

Decisions

DecisionWhy
Keeper relays the signed result; TEE sends no transaction Keeps gas/nonces/stuck-tx out of the enclave. The store verifies the signature, so the keeper is liveness, not trust — anyone can submit.
RPC, not FDC, for supply reads FDC adds a round trip and complexity; the TEE is already the trust anchor. Redundancy instead: 3 providers/chain, 2-of-3 or all-3 — configurable.
Query an explicit block number, never a tag Providers disagree on latest — and, measured, on finalized too. Resolve the tag to a number per provider, take the minimum, query everyone there.
Read decimals() per chain They differ: 18 on Ethereum, 6 on Flare/Songbird.
On-chain payload carries price only Hex may consider reserve figures sensitive. Note GET /state is public too, so it can't hold them either.
Endpoints on-chain, credentials by direct instruction Publishing which RPC providers we read is the point — it is what makes the data sources verifiable. Credentials go off-chain via /direct-instruction: no gas, no permanent on-chain record, instant rotation, and no secret-handling path in Solidity. There is deliberately no host allowlist: endpoints are unconstrained so providers rotate without rebuilds, and the owner key is therefore price-controlling by decision (Findings §15).
Fail closed Source down or value implausible → publish nothing, let the timestamp age. Never guess a price.
Feed never reverts on stale data FtsoV2 forwards calls through, so a revert becomes a liveness outage for every consumer. Return last price + ageing timestamp; pause freezes rather than throws.
